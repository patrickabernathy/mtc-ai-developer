Sometimes watching someone do it once is worth more than reading about it. Two videos here: a
short one showing the exact workflow we use in class — Git and GitHub from inside VS Code,
using the Source Control panel instead of typing commands — and a longer, slower one that
explains what GitHub itself actually is.

Watch, then do it yourself on your own repo. Nothing sticks until your own hands are on it.

---

## Start here

### [How to use Git and GitHub in VS Code — Tutorial for beginners](https://www.youtube.com/watch?v=NFjz1AGKA4c)

**GitHub** · 9 minutes

This is the one to watch first. It's made by GitHub themselves, so what you see on screen
matches what you'll actually see in VS Code and on github.com. It walks the whole loop —
getting a repo onto your machine, making a change, staging it, committing it, and pushing it
back up — without ever leaving the editor.

Nine minutes, start to finish. Watch it before class if you're feeling behind, or right after
if the demo went by too fast.

## Then: GitHub itself

### [How to use GitHub as a beginner (no terminal) — GitHub Desktop tutorial](https://www.youtube.com/watch?v=2SgI1kAczfk)

**Coder Coder** · 24 minutes

The video above covers our whole workflow inside VS Code — that one alone is enough to do the
work. This one is here for the other half of the picture: **GitHub itself.** It's much longer
and much slower, and it explains the things the short version assumes you already know — what
a repository actually is, what a commit is, why branches exist, and what a pull request is
doing when you open one.

If the words are the part tripping you up rather than the buttons, watch this one.

**One thing to know going in:** it demonstrates using **GitHub Desktop**, a separate free app
from GitHub. We don't use GitHub Desktop in this class and you don't need to install it. Watch
it for the GitHub half — the website, the vocabulary, the concepts — and ignore the app. Every
button it clicks in GitHub Desktop has a twin in VS Code's Source Control panel; they sit in
different places and mean the same thing.

## Watching these well

A few things worth doing, whichever video you pick:

- **Watch it once without pausing.** Just get the shape of it. Don't try to follow along yet.
- **Then watch it again with VS Code open** next to it, and do each step on your own repo as
  it happens. Pause constantly. This is the pass that actually teaches you something.
- **Expect small differences.** VS Code and GitHub both change their interface a few times a
  year, so a button may have moved or been renamed since the video was recorded. The steps
  are the same even when the pixels aren't — if you can't find something, that's a question
  for class, not a sign you did it wrong.
- **The panel is just running Git for you.** Every button in the Source Control panel maps to
  a command on the [Git cheat sheet](git-cheat-sheet.md). Clicking **Commit** runs
  `git commit`. Clicking **Sync** runs `git pull` and then `git push`. Knowing both ways to
  do it is the goal — the buttons for speed, the commands for when the buttons don't explain
  what went wrong.
