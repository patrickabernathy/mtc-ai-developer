Sometimes watching someone do it once is worth more than reading about it. These are short
videos of the exact workflow we use in class — Git and GitHub from inside VS Code, using the
Source Control panel instead of typing commands.

Watch one, then do it yourself on your own repo. Nothing sticks until your own hands are on it.

---

## Start here

### [How to use Git and GitHub in VS Code — Tutorial for beginners](https://www.youtube.com/watch?v=NFjz1AGKA4c)

**GitHub** · 9 minutes

This is the one to watch first. It's made by GitHub themselves, so what you see on screen
matches what you'll actually see in VS Code and on github.com. It walks the whole loop —
getting a repo onto your machine, making a change, staging it, committing it, and pushing it
back up — without ever leaving the editor.

Nine minutes, start to finish. Watch it before class if you're feeling behind, or right after
if the demo went by too fast.

## Watching these well

A few things worth doing, whichever video you pick:

- **Watch it once without pausing.** Just get the shape of it. Don't try to follow along yet.
- **Then watch it again with VS Code open** next to it, and do each step on your own repo as
  it happens. Pause constantly. This is the pass that actually teaches you something.
- **Expect small differences.** VS Code and GitHub both change their interface a few times a
  year, so a button may have moved or been renamed since the video was recorded. The steps
  are the same even when the pixels aren't — if you can't find something, that's a question
  for class, not a sign you did it wrong.
- **The panel is just running Git for you.** Every button in the Source Control panel maps to
  a command on the [Git cheat sheet](git-cheat-sheet.md). Clicking **Commit** runs
  `git commit`. Clicking **Sync** runs `git pull` and then `git push`. Knowing both ways to
  do it is the goal — the buttons for speed, the commands for when the buttons don't explain
  what went wrong.
